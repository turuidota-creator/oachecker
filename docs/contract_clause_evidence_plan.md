# 合同条款证据包方案

## 背景

当前插件里的合同能力更偏向“付款摘要”：

- 本地筛付款相关候选条款
- 当前版本直接使用本地规则整理
- 当前摘要入口统一为本地规则接口

这条链在 MVP 阶段够用，但它有一个明显问题：

- 它更像“给结论”
- 不够像“给证据”

对财务审核来说，真正关键的往往不是一句总结，而是：

- 命中的到底是哪几条
- 这些条款在第几页
- 前后文有没有例外条件
- 同一主题下是否存在互相冲突的约定

因此，合同模块下一阶段更适合从“单句摘要”升级成“主题化条款证据包”。

## 核心目标

把合同相关展示从“一个结果”调整成“两类主题 + 多条证据 + 冲突提醒”：

1. 固定两个主题入口
   - `付款条件`
   - `合同期限`
2. 每个主题展示 Top N 条款，而不是只展示 Top 1 句
3. 每条结果展示完整证据，而不是只有一句压缩结论
4. 支持展开上下文，方便看例外条款
5. 对限制性表达做显式提醒
6. 对同主题下的冲突表达做人工确认提醒

## 为什么这条路更适合财务审核

### 1. 比“只给一句摘要”更可信

财务审核要的是“我为什么该信这个结果”，不是只要一句“系统说付款条件是什么”。

如果界面能直接给出：

- 条款编号
- 原文片段
- 页码
- 前后文
- 限制词
- 冲突提醒

那么用户可以非常快地完成二次确认。

### 2. 比“只做压缩摘要”更稳

规则检索加证据展示，比单纯追求一句压缩总结更适合当前审核场景。原因包括：

- 证据边界更清晰
- 不容易把多个条款压成一个结论
- 输出口径更稳定

## 推荐路线

主方案建议是：

`本地主题检索 + 证据展示 + 限制词提醒 + 冲突提醒`

补充说明：

- 当前版本只保留本地规则链路
- 这里讨论的是现有本地证据方案，不包含任何外部摘要能力

## 产品形态

### 1. 固定两个主题入口

建议在合同区域固定展示：

- `付款条件`
- `合同期限`

说明：

- “合同期间”建议统一改成“合同期限”，更贴近合同语言
- 这两个主题是付款审核里最稳定、最常用、最适合人工确认的两个入口

## 合同类型覆盖范围

游戏公司常见合同类型不只是一种“采购合同”，关键词和召回策略必须覆盖至少这些场景：

- `物业租赁 / 水电物业`
  - 典型关注：租金、物业费、水电费、押金、租赁期限、自动续展
- `买量投放 / 广告代理 / 渠道投放`
  - 典型关注：充值垫款、后台消耗、对账确认、KPI、达标、扣减、补量
- `美术视频外包`
  - 典型关注：初稿、终稿、成片、源文件、修改次数、验收通过后付款
- `软件授权 / 订阅 / 技术服务`
  - 典型关注：账号开通、授权费、订阅期、续费、维保、以订单为准
- `软著 / 版权代理`
  - 典型关注：受理通知书、登记证书、代理费、失败退费
- `问卷调查 / 用户研究`
  - 典型关注：样本量、有效样本、答卷、数据清洗、研究报告、按比例扣减

这意味着：

- 词表不能只围绕 `付款 / 发票 / 验收`
- 也不能只围绕 `KPI`
- 必须同时覆盖“行业执行语言”和“合同法务语言”

### 2. 每个主题展示 Top N 条

#### 付款条件

- 默认展示 `3` 条
- 可扩展到 `5` 条

#### 合同期限

- 默认展示 `2` 条
- 可扩展到 `4` 条

说明：

- 默认不要把候选条款全部堆出来
- 先给最相关的少数条，再允许展开查看更多

### 3. 每条结果的展示字段

每条命中结果至少展示：

- `条款编号`
- `小段正文`
- `页码`
- `命中关键词`

其中：

- `条款编号`：如 `3.1`、`第五条`、`付款方式`、`租金支付方式`
- `小段正文`：不是只取一个短句，而是取能看懂条件的一个小段
- `页码`：帮助用户快速回到原文
- `命中关键词`：在片段里高亮，例如 `付款`、`发票`、`验收`、`工作日`、`期限`、`自动续展`

### 4. 支持展开上下文

每条结果可点击展开：

- `上一条`
- `当前条`
- `下一条`

原因：

- 合同中的例外、前提、补充义务，经常就在前后文
- 只看单句很容易漏掉“除非”“另有约定除外”“验收后支付”这类关键限制

### 5. 做“补充 / 限制”标记

如果命中以下表达，给出显式提醒：

- `但`
- `除非`
- `前提是`
- `经……后`
- `如未……`
- `有权暂缓`
- `自动续展`
- `另有约定除外`

建议 UI 上用黄标或提醒标签：

- `有限制`
- `有前提`
- `有例外`
- `自动续展`

### 6. 做“可能冲突”提醒

如果同一主题下同时命中多个可能不一致的表达，则提示人工确认。

例如合同期限同时命中：

- `固定期限一年`
- `自动续展一年`
- `具体期限以订单为准`

则不应该硬给一个结果，而应该提示：

- `发现多个与合同期限相关的条款，请人工确认`

同理，付款条件也可提示：

- `发现多个与付款条件相关的条款，请人工确认`

## 检索与排序方案

## 1. 先做条款切分

在进入主题检索前，先把合同文本切成可引用的条款单元：

- 编号条款：`1`、`1.1`、`3.2`、`第五条`
- 标题条款：`付款方式`、`合同期限`、`租赁期限`
- 无编号自然段：保留段落边界

每个单元至少保存：

- `clauseId`
- `title`
- `text`
- `page`
- `prevClause`
- `nextClause`

## 2. 再按主题检索

### 付款条件关键词

建议优先检索：

- `付款`
- `支付`
- `结算`
- `发票`
- `验收`
- `工作日`
- `付款条件`
- `付款方式`
- `账期`
- `月结`
- `预付款`
- `尾款`
- `分期`

### KPI / 投放成效类付款条件关键词

这一类合同不能只靠 `付款 / 支付 / 发票 / 验收` 召回，因为真正的付款前提常常写成：

- 达成某个投放效果后付款
- 按 KPI 完成度结算
- 按点击、曝光、转化、激活、留存、播放量等指标结算
- 未达标时按比例扣减、延期支付或不予结算

因此建议把这类词单独作为“付款条件强信号”：

- `KPI`
- `考核`
- `达标`
- `未达标`
- `完成率`
- `结算依据`
- `效果`
- `效果达成`
- `投放`
- `曝光`
- `点击`
- `转化`
- `激活`
- `留存`
- `ROI`
- `CPA`
- `CPS`
- `CPM`
- `CPC`
- `播放量`
- `下载量`
- `注册量`
- `交付结果`
- `数据验收`
- `对账确认`
- `扣减`
- `扣费`
- `补量`
- `退款`

这些词建议有两种用法：

- 作为召回关键词，提高条款进入候选池的概率
- 作为加权关键词，提高“效果达成后付款”类条款的排序

### KPI / 投放类条款的特殊提醒

对这类合同，建议额外提示以下风险：

- `付款触发条件不是单纯时间，而是结果达成`
- `付款可能依赖 KPI 达成、数据验收或对账确认`
- `未达标时可能存在扣减、补量、延期支付或不予结算`

也就是说，在投放类合同里：

- `KPI / 数据 / 对账 / 达标条件`

本身就是付款条件的一部分，而不是普通背景描述。

### 合同期限关键词

建议优先检索：

- `期限`
- `期间`
- `有效期`
- `租赁期`
- `服务期`
- `起至`
- `自`
- `至`
- `终止`
- `到期`
- `续展`
- `自动续展`
- `以订单为准`

## 3. 排序逻辑

建议按综合得分排序，而不是只按单关键词命中：

- 标题命中优先
- 条款编号结构完整优先
- 多关键词同条命中优先
- 包含强约束词优先
- 只提到边角信息的段落降权

可参考得分项：

- `topicScore`
- `keywordDensity`
- `headingBoost`
- `constraintBoost`
- `pagePenalty`
- `noisePenalty`

## 公开样本校验结论

基于公开合同、政府采购附件和上市公司披露文件做了一轮样本校验后，关键词策略需要补一个重要认知：

- 真实合同里不一定直接写 `KPI`
- 很多付款前提会写成更业务化的表达
- 期限相关条款也常常以 `续签 / 自动续展 / 具体以订单为准` 这类方式出现

### 1. 付款条件里应补强的真实表达

在公开样本里，以下表达频繁出现，而且都属于付款条件强信号：

- `据实结算`
- `审核确认`
- `结算表`
- `收到发票后`
- `工作日内支付`
- `阶段性验收`
- `总体验收`
- `整改`
- `考核后支付`
- `待考核合格后支付`
- `未达标扣减`
- `服务质量考评`
- `满意度调查`
- `达标`
- `不合格`
- `终止合同`

这意味着“付款条件”主题不能只搜：

- `付款`
- `支付`
- `发票`
- `验收`

还要把“考核 / 评分 / 扣减 / 整改 / 结算表 / 审核确认”纳入强信号。

### 2. KPI 类合同不能只搜字面上的 KPI

公开合同里，字面上的 `KPI` 并不总是高频词。

很多合同会写成：

- `考核评分`
- `服务质量考评`
- `未达标扣减`
- `按结果结算`
- `据实结算`
- `对账确认`
- `审核确认后开票`

因此，对于投放、代运营、推广、服务外包类合同，建议把下面这些词和 `KPI` 同等看待：

- `考核`
- `评分`
- `达标`
- `未达标`
- `扣减`
- `补贴`
- `服务质量`
- `满意度`
- `对账`
- `审核确认`
- `结果`
- `效果`

### 3. 合同期限里应补强的真实表达

在公开样本里，期限和覆盖关系常出现这些表达：

- `自动续展`
- `自动延长`
- `一年一签`
- `续签`
- `服务期满后根据考评决定是否续签`
- `具体以订单为准`
- `框架合同`
- `持续有效`
- `除非一方书面通知终止`

因此“合同期限”主题不能只搜：

- `期限`
- `有效期`
- `起至`
- `到期`

还要把下面这组词提高优先级：

- `续签`
- `自动续展`
- `自动延长`
- `订单`
- `以订单为准`
- `框架合同`
- `持续有效`
- `终止`
- `书面通知`

### 4. 推荐的词表调整结论

基于这轮样本，建议把召回词分成三层：

#### 第一层：直观主题词

- `付款`
- `支付`
- `结算`
- `发票`
- `验收`
- `期限`
- `有效期`
- `续签`

#### 第二层：真实合同高频业务词

- `据实结算`
- `审核确认`
- `结算表`
- `考核`
- `评分`
- `达标`
- `未达标`
- `扣减`
- `整改`
- `服务质量考评`
- `一年一签`
- `自动续展`
- `具体以订单为准`

#### 第三层：限制 / 覆盖 / 冲突词

- `但`
- `除非`
- `另有约定除外`
- `经……后`
- `如未……`
- `有权暂缓`
- `自动续展`
- `书面通知`
- `终止`
- `以订单为准`

## 这轮联网校验带来的结论

如果只把关键词设计成“合同教科书语言”，召回效果会明显不够。

更好的做法是同时覆盖三类表达：

- 法务语言：`付款方式`、`合同期限`、`自动续展`
- 业务语言：`据实结算`、`考核后支付`、`服务质量考评`
- 效果语言：`KPI`、`效果达成`、`对账确认`、`未达标扣减`

## 冲突检测方案

冲突检测不需要一上来做复杂语义推理，第一版先做规则化提醒即可。

### 付款条件冲突线索

例如同一合同同时出现：

- `验收后 15 个工作日内支付`
- `收到发票后 10 个工作日内支付`
- `另有订单约定的，以订单为准`

这时系统不应只显示其中一句，而应提示：

- 存在多个付款触发条件
- 存在多个付款时限
- 存在“以订单为准”覆盖条件

对于投放 / KPI 类合同，还应额外关注：

- `达标后付款`
- `按 KPI 完成率结算`
- `数据确认后付款`
- `未达标按比例扣减`
- `补量完成后再结算`

如果同一主题下同时出现“固定付款时限”和“效果达成后付款”两类表达，应直接提示：

- `发现时间型付款条款与 KPI 型付款条款并存，请人工确认真实付款前提`

### 合同期限冲突线索

例如同时出现：

- `合同期限为一年`
- `合同到期自动续展一年`
- `具体服务期限以订单为准`

则给出：

- `固定期限`
- `续展约定`
- `订单覆盖约定`

并提示人工确认。

## 方案说明

### 条款证据包方案

优点：

- 可解释
- 可复核
- 适合财务和法务联看
- 输出稳定
- 便于做限制词和冲突提醒

缺点：

- 前期需要把条款切分、排序、上下文展示做好
- 看起来不像“一句话就结束”，UI 设计要克制

## 结论

推荐直接采用条款证据包作为当前主方案。

## 与现有实现的关系

这套方案不是推翻现有合同链路，而是升级展示和判读层：

保留：

- 合同附件下载
- PDF / DOCX / OCR 提取
- 本地条款筛选
- 本地摘要与提醒链路

新增：

- 条款级切分
- 主题化检索
- Top N 证据展示
- 页码与关键词高亮
- 上下文展开
- 限制词提醒
- 冲突提醒

弱化：

- “只给一条付款摘要”的展示方式

## 分阶段落地建议

### Phase 1：证据包 MVP

目标：

- 固定两个主题入口
- 每个主题展示 Top N 条款
- 展示条款编号、片段、页码、命中词

暂不做：

- 复杂冲突归因

### Phase 2：上下文与提醒

目标：

- 支持展开 `上一条 / 当前条 / 下一条`
- 支持限制词标记
- 支持基础冲突提醒

## 建议的前端展示原则

- 默认简洁，不把所有条款一次性铺开
- 先给主题，再给少量证据，再允许展开
- 先给“证据与提醒”，再给“摘要”
- 对“冲突”“例外”“自动续展”这类词汇，用视觉提示明确区分

## 一句话结论

对于付款审核场景，最优解不是“先压缩成一句总结”，而是“先把相关条款、限制条件和冲突点找准，再把证据展示清楚”。
