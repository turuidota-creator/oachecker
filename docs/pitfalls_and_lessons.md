# OA 付款审核插件踩坑总结

这份文档专门记录这轮重构中遇到过的坑、症状、原因、修复方式和后续建议。

## 1. VPN / 代理导致自动化浏览器打不开 OA

### 症状

- 手动浏览器偶尔能开 OA
- 自动化脚本访问 `http://oa.cyou-inc.com/index` 报 `ERR_HTTP_RESPONSE_CODE_FAILURE`

### 原因

- 自动化浏览器仍然走了系统代理或 VPN 代理
- OA 内网地址没有走直连

### 修复

- 在测试脚本里强制加直连参数
- 系统代理补白名单：
  - `oa.cyou-inc.com`
  - `*.cyou-inc.com`
  - `ai.cy.com`
  - `10.*`
  - `<local>`

### 当前策略

- [test_rebuild_single_case.py](C:/Users/turui/Documents/Playground_oa_finance_rebuild/test_rebuild_single_case.py) 已内置绕过代理参数

## 2. OA 页面自己的控制台报错干扰判断

### 常见红字

- `finance.cyou-inc.com` 的 CORS
- `setValue`
- 各种 `micro-app` 报错

### 原因

- 这些大多是 OA 页面自身的微应用错误
- 不是插件自身的主错误

### 教训

- 不要只盯浏览器控制台
- 要优先看插件自己的诊断信息和结果 JSON

## 3. service worker 里跑 pdf.js / OCR 问题很多

### 症状

- `No "GlobalWorkerOptions.workerSrc" specified`
- `Setting up fake worker failed`
- `Worker is not defined`

### 原因

- MV3 service worker 对 `pdf.js` 和 OCR 运行环境不友好
- worker、wasm、动态 import 都容易踩坑

### 修复

- 避免把复杂 PDF/OCR 工作放在 service worker 里硬跑
- 改成在更稳定的上下文里执行 PDF 文本提取和 OCR

## 4. pdf.js 中文 PDF 字体警告很多

### 症状

- `translateFont failed`
- `TT: undefined function`
- `cMapUrl` 相关 warning

### 原因

- 中文 PDF 缺字库/字形映射资源时容易报警

### 修复

- 配置 `cMapUrl`
- 配置 `standardFontDataUrl`
- 降低无意义 warning 对控制台的干扰

## 5. OCR 不能依赖外网语言包

### 症状

- 换一台电脑后 OCR 不稳定
- 首次使用 OCR 要联网

### 原因

- 原始方案默认从外网拉 `tessdata`

### 修复

- 把 `chi_sim` 和 `eng` 语言包放到扩展本地
- 通过 `manifest.json` 暴露本地资源

## 6. 扫描版 PDF 只扫前两页会漏账号

### 症状

- 合同 PDF 肉眼能看到收款账号
- 插件却识别不到

### 原因

- 扫描版 PDF OCR 只扫前两页
- 账号实际在更后面的页里

### 修复

- 短文档多扫几页
- 长文档扫前几页和后几页

## 7. 只靠文件名识别发票完全不够

### 症状

- `vsg_output_xxx.jpg` 这类发票图不被当成发票
- 金额和公司命中了，但来源仍显示合同

### 原因

- 文件名看不出来是发票
- 旧逻辑只按文件名做角色判断

### 修复

- 改成按 OCR / 正文内容识别发票
- 强化发票优先覆盖逻辑

## 8. 付款单字段核实付款单自己是严重偏航

### 症状

- 前端出现“已在付款单字段中核实收款公司名称”之类文案

### 原因

- 付款单字段被错误地当成证据来源

### 修复

- 明确禁止自证
- 付款单字段只做被核验目标

## 9. 缺证据不等于不一致

### 症状

- 发票里没账号时，账号直接报红
- 合同里没账号时，也直接报红

### 原因

- 旧规则把“没提取到”误当成“冲突”

### 修复

- 统一改成黄灯
- 只有发现明确冲突证据才给红灯

## 10. 老 workflow 页面链接不可靠

### 症状

- `workflow.cyou-inc.com` 页面打不开
- 但历史接口有时还能拿到数据

### 原因

- 页面链路和历史 API 权限不是同一套
- `workflow` 域名有时路由本身就不通

### 修复

- 尽量优先走历史接口
- 不把老页面链接当唯一真相来源

## 11. `sourceInstId` 在部分验收页里是必须的

### 症状

- 验收流程链接明明存在
- 但详情页读不出来

### 原因

- 某些流程详情依赖 `sourceInstId`

### 修复

- 保留并传递 `sourceInstId`

## 12. 合同页可读，不代表合同附件已读全

### 症状

- 合同有效期已经出来了
- 但付款条件仍然是“未提取”

### 原因

- 很多时候只是读到了合同页表单
- 没有稳定读到合同附件正文，或正文里没成功提取条款

### 修复

- 新增合同处理状态：
  - 是否进入合同页
  - 发现几个合同附件
  - 成功解析几个
  - 条款来源是表单还是附件

## 13. 合同附件会出现重复和 hash 名

### 症状

- 前端显示合同附件很多
- 但肉眼看到没那么多
- 有些名字是一串 hash

### 原因

- 同一文件可能以多种形式进入候选集
- 有些是物理文件名，有些是人类文件名

### 修复

- 改进去重
- 更偏向保留人类可读文件名
- 前端展示时排掉明显无意义的 hash 名

## 14. 字段映射太宽会把邮箱当银行账号

### 症状

- 合同页里某个字段其实是邮箱
- 却被错误当成账号来源

### 原因

- 账号候选字段过宽
- 没做足够的“像银行账号”的校验

### 修复

- 对账号候选做更严格过滤
- 像邮箱这类值不再进入账号证据

## 15. 图片 OCR 不能只跑整图一次

### 症状

- 发票截图里肉眼能看到金额
- 但插件识别不到

### 原因

- 单轮 OCR 对小字和右下角金额不稳定

### 修复

- 原图 OCR
- 灰度增强 OCR
- 高对比 OCR
- 局部裁切 OCR
- 数字专用 OCR

## 16. 合同摘要不是“接上模型”就结束

### 症状

- 模型很快能给出付款摘要
- 但发送给 AI 的预览里仍然可能混入过长原文
- 用户会直观感觉“这和直接发合同差别不大”

### 原因

- 早期版本虽然不是整份合同外发
- 但本地筛出来的候选条款还是可能过长
- 脱敏又是规则型补洞，不是结构化最小外发

### 教训

- “不是整份合同外发”不等于“已经足够安全”
- 要同时控制：
  - 候选条款长度
  - 候选条款内容范围
  - 脱敏强度
  - UI 是否误把原文露出来

### 当前策略

- 候选条款优先收缩成关键词句子窗口
- 去掉明显的签章区、联系人区、地址区、账户信息区
- 发送预览默认收起
- 收起后正文不再显示

## 17. 规则型脱敏只能算过渡方案

### 当前能脱的

- 合同名 / 附件名
- 流程号 / 合同号 / 文档号
- 日期
- 邮箱
- 手机号
- 身份证号
- IP
- 金额
- 百分比 / 税率
- 长账号 / 长编号
- 银行名
- 一些标签后的人名和字段值

### 当前仍然不该夸大的点

- 这不是严格保密最终版
- 它更像内部试跑版
- 因为它本质上还是：
  - 本地筛原始条款
  - 脱敏后外发

### 更稳的终态

- 本地先抽结构化 facts
- 外部模型只接 facts
- 不再看到原始条款文本

## 18. UI 折叠如果做不好，会把安全感直接打没

### 症状

- 标题写着“发送给 AI 的预览（脱敏后）”
- 但下面还挂着原始条款卡片
- 收起后正文没有完全隐藏

### 教训

- 这类 UI bug 不只是样式问题
- 它会直接削弱用户对“已经脱敏”的信任

### 当前策略

- 发送预览做成完整折叠区
- 默认收起
- 收起时内容不展示
- 原始条款不再挂在预览区下面

## 19. 当前最值得继续盯的点

如果后面继续优化，最值得优先盯的是：

1. 合同付款条件提取
2. 合同附件读全和附件统计
3. 合同摘要外发边界
4. 更多单据回放和边界回归

## 20. 排查建议

如果下一次再遇到“这张单不对”，建议按这个顺序排：

1. 先看插件侧边栏，不先看 OA 控制台
2. 看 `result.json`
3. 看三张主卡片到底是哪一项没命中
4. 看合同处理状态
5. 看合同摘要有没有发送、发了什么
6. 看来源是不是发票、合同还是其他附件
7. 最后再去查附件正文提取和 OCR

## 21. 侧边栏只设 `max-height`，不代表用户就一定能滚动

### 症状

- 面板里其实已经渲染出了关联单据和合同摘要
- 但下面一截被截断
- 鼠标滚轮和触控板都滚不下去

### 原因

- 外层容器只有 `max-height`
- 内层卡片没有被压进固定高度
- 结果卡片自己长到了视口外
- 内部滚动区拿不到正确剩余高度，于是浏览器判断“不需要滚动”

### 修复

- 外层容器改成 `top + bottom` 固定高度
- 卡片改成 `height: 100%`
- `.oa-finance-rebuild-body` 作为唯一滚动区

### 教训

- “内容在 DOM 里但看不见”先查布局，不要先怀疑采集失败
- 排查时直接看：
  - `clientHeight`
  - `scrollHeight`
  - `scrollTop`

## 22. 自动化能进 OA，不代表手动浏览器也一定能进

### 症状

- 回放脚本能正常打开 OA
- 人手点 Edge 却打不开，或者很不稳定

### 原因

- 本机系统浏览器代理仍然走 `127.0.0.1:1080`
- 而回放脚本显式加了直连参数，绕开了代理

### 修复

- 增加直连启动脚本：
  - `scripts/open_oa_direct.ps1`
  - `scripts/open_oa_direct.cmd`
- 增加系统代理例外脚本：
  - `scripts/set_oa_proxy_bypass.ps1`

### 教训

- `WinHTTP` 直连不等于浏览器代理也直连
- 遇到“同一台机器、脚本能进、手动不能进”时，优先查系统代理和例外名单

## 23. 补充协议类合同没有直接付款条款，不等于合同信息提取失败

### 症状

- 合同页能打开
- 合同附件也读到了
- 但合同摘要仍然显示“未提取到明确付款条件”

### 原因

- 这类合同常见形态是“补充协议 + 报价单 / 费用表”
- 正文重点在：
  - 新增什么服务
  - 原合同继续有效
  - 合同期如何延续
- 而不是直接出现“付款方式 / 付款条件 / 支付条款”

### 修复

- 在合同分析层增加补充协议回退摘要
- 当显式付款条款抽不到时，优先从附件里补：
  - `按原合同约定执行`
  - `月租 / 月费 / 一次性费用`
  - `服务期 / 自动延期`

### 真实案例

- `DDFK-202602040012`

这张单最终能稳定提到：

- `2.2 本协议未尽事宜，按原合同约定执行`
- `SD-WAN服务（重庆） 10M ¥2,800`
- `月租服务费用`

### 教训

- 对合同摘要来说，“没命中付款关键词”不等于“没有可展示合同信息”
- 补充协议、租赁、框架协议这几类都要防止被误判成“未提取”

## 24. 采购订单供应商字段不能用过宽的兜底标签
### 症状

- 采购订单页面肉眼看供应商名称和付款单收款公司一致
- 系统却把“收款公司与订单供应商”判成异常

### 原因

- 采购订单详情里常常同时出现多个公司相关字段
- 如果直接按 `供应商 / 收款公司 / 公司` 这类宽标签取第一个命中的值，很容易拿到错误字段
- 后面再和付款单收款公司比对时，就会出现“页面看着一致，系统却判异常”

### 修复

- 对采购订单供应商改成“候选值收集 + 优先匹配”
- 先只收集明确的 `订单供应商 / 供应商名称 / 供应商`
- 如果候选里有和付款单收款公司能松匹配上的，优先选它
- 只有明确供应商字段完全没拿到时，才退回页面快照兜底

### 教训

- 公司类字段不能只靠“第一个像公司名的值”来判定
- 采购订单、合同、验收这几类页面都要尽量先走明确业务字段，再做模糊兜底
# 25. 前端频繁显示乱码时，先查源码是否已混入 mojibake，而不是先怀疑浏览器 UTF-8
### 症状

- 扩展前端偶发或频繁出现 `鍥藉唴PR`、`閾炬帴寮傚父`、`未找�?` 这类乱码
- 有些地方不只是显示坏了，连字段提取也开始异常

### 原因

- 不是浏览器把 UTF-8 页面渲染错了
- 是源码里的文案和字段标签已经被错误转码后写回文件，属于 mojibake 污染
- 一旦坏串进入 `analyzer.js` 这类核心文件，既会影响前端展示，也会影响字段匹配

### 修复

- 先全局扫描扩展源码里的典型乱码串，而不是只看页面表现
- 优先修复会直接展示给用户、以及会参与字段提取的字符串
- 对自动修复后的结果再做二次复扫，防止残留 `�` 或被误替换成别的字符

### 教训

- “看起来像编码问题”和“真的是运行时编码问题”不是一回事
- 对这类项目，最危险的是坏串混进业务标签数组，因为那会让抽取逻辑和展示层一起失真
