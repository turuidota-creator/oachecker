# OA 付款审核插件经验教训

这份文档只保留可复用的排查原则和近期关键结论。完整事故过程、旧实现细节和长日志以 git 历史为准，避免日常排查时被流水账淹没。

## 维护规则

- 新增经验时优先写成“现象 / 原则 / 动作”，每条控制在 3 个要点内。
- 已经沉淀成稳定原则的内容不要重复追加事故复盘。
- 影响运行模型的变化必须同步更新根 README、`docs/README.md` 和 `docs/rebuild_plan.md`。

## 核心原则

### 入口与触发

- 详情页入口不能只依赖悬浮面板 root 自己出现；必须由全站常驻脚本提供页面内入口兜底。
- 详情页进入时只能被动读取缓存，不能自动开跑审核；自动审核必须由用户点击入口触发。
- 页面内 `自动审核` 只负责稳定打开/触发，审核结果和手动重跑仍放在悬浮面板里。
- SPA 路由切换必须监听 URL 和 DOM 变化，离开详情页要清理入口，避免重复插入或把详情入口带回列表页。

### 缓存与标识

- 业务缓存键以规范化后的 `processCode` 为主，统一大写，并附带 `buildTag + cachedDay` 做失效控制。
- URL 里的 detail id 只能当线索，不能当稳定业务号；详情页缓存回放要优先从 URL、页面快照和付款目标里识别流程号。
- 批量审核写缓存和详情页读缓存必须走同一套规范化逻辑，否则会出现“批量已完成，单个仍读不到”的假失败。
- 行为变化或规则口径变化后要同步更新 `buildTag` 或缓存 schema，避免旧结果伪装成新结果。

### 异步与进度

- 每次详情页分析和列表页批量任务都要生成独立 `requestId`，进度回调只允许当前活动请求消费。
- 旧请求、慢请求、跨 tab 回调都要能被识别并丢弃，不能覆盖新一轮审核状态。
- 列表页批量审核需要受控并发，不要把 OA 详情、附件下载、OCR 和合同链路一次性全打满。
- UI 状态必须区分“读取缓存中”“审核中”“缓存命中”“缓存未命中”，避免用户误以为按钮没反应。

### 数据源一致性

- 列表页批量审核和详情页单条审核要共享同一套页面快照、流程数据、附件解析和结果汇总逻辑。
- `flowFormData`、页面表单字段和接口详情都可能不完整，字段采集必须有兜底和来源标注。
- 三张主核对卡片不能用“付款单自己核实自己”当最终证据；发票、合同、验收、采购订单等外部证据优先。
- OA 页面里的 select/radio 选项文本、乱码字段和隐藏字段容易污染结果，提取时要保留上下文并做噪声过滤。

### 附件与来源链接

- 带签名时间窗的 COS URL 只能当瞬时下载凭证，不能长期缓存给 UI；点击打开时要重新刷新凭证。
- 关联流程附件要保留 `sourceInstId`、来源流程号和来源页面，方便重新定位和刷新链接。
- Office/XML 解析只取可见文本，不能把批注、修订、关系文件或隐藏元数据当业务正文。
- 主附件、意见附件、历史流程附件和关联流程附件来源不同，不能只按文件名粗暴去重。

### OCR 与性能

- OCR 是兜底能力，优先使用结构化字段、正文文本和可直接抽取的 PDF/DOCX/XLSX 内容。
- MV3 background 不适合长期承载 Tesseract worker；OCR worker 池放在宿主页 `ISOLATED` world，由 background 编排调用和释放。
- 批量任务结束时要显式释放 OCR 池，空闲时再做 idle terminate，兼顾速度和内存。
- 图片和扫描 PDF 多轮 OCR 要限流，并记录命中来源，避免重复识别同一附件。

### UI 与发布

- 发布态文案要去掉“重构版”等阶段性词汇，用户可见入口保持同一个产品名。
- 入口按钮要像 OA 原生操作的一部分，不要像广告浮层；固定兜底入口层级要低于完整审核面板。
- 面板、按钮、卡片尺寸要稳定，状态变化不能引起大幅布局跳动。
- 插件发布包的 zip 根目录必须是扩展根目录，不要多包一层项目目录。

### OA 环境

- OA 内网访问失败时先查代理/VPN 白名单，自动化浏览器要显式绕过代理。
- `finance.cyou-inc.com` CORS、`micro-app` 和 `setValue` 等红字常是 OA 自身问题，不要直接归因到插件。
- 新旧流程系统、`flowable`、`history`、老 `requestid` 都要兼容；不要只按一个接口形态写死。

## 近期关键修复

### 2026-04-17 UTF-8 乱码与旧 OCR 路径清理

- 现象：活动代码里的乱码文案和乱码正则会让合同关键词、金额上限识别或错误提示失真；迁移到 OCR bridge 后旧 in-tab 路径仍残留。
- 原则：中文项目的活动逻辑不能保留 mojibake；测试应锚定当前主链路，而不是已废弃实现里的字符串。
- 动作：修复合同兜底关键词、金额上限正则、PDF/OCR/扩展通信错误文案；删除旧 `extractPdfTextInTab` / `extractImageTextSafe` 并更新 OCR guard。

### 2026-04-17 多发票合计金额

- 现象：一张付款单挂多张发票时，单张发票金额都不等于付款金额，容易把实际合计通过的单据识别成未通过。
- 原则：结构化发票明细存在多张时，金额核对应以全部发票价税合计为准，不能退回单张发票命中。
- 动作：多发票合计命中时生成合计证据；票种仍要求每张参与发票均识别为增值税专用发票。

### 2026-04-17 安装说明要按文件夹选择器视角写

- 现象：浏览器“加载已解压的扩展程序”打开的是文件夹选择器，用户在共享目录里只看得到 `assets`、`bg`、`node_modules`、`page`、`shared` 等子文件夹，看不到 `manifest.json`。
- 原则：面向用户的安装说明不能要求在选择器里确认某个文件；应强调选中扩展根文件夹本身。
- 动作：安装教程改为让用户停在 `\\10.1.0.230\财务部\总账组\OA审批插件` 并直接点击“选择文件夹”，不要进入任何子目录。

### 2026-04-17 共享目录发布同步

- 现象：共享目录 `\\10.1.0.230\财务部\总账组\OA审批插件` 已经按扩展根目录展开，里面直接包含 `manifest.json`、`background.js`、`content.js` 等文件。
- 原则：同步当前版本时以 `oa_finance_audit_rebuild_extension/` 为源目录，不要复制项目根、`dist/` 历史 zip 或各类 `tmp_*` 调试目录。
- 动作：同步前先跑本地规则脚本；同步后用文件数量、manifest 版本和关键文件时间戳确认共享目录已更新。

### 2026-04-16 PR付款链路核查

- 现象：容易把 PR付款当成独立落后模块；实际 `GNTYYFK-*` 和 `DDFK-*` 共享同一套主分析、缓存和 OCR 管线。
- 原则：核查新流程能力时先看共享入口、`flowType` 分支、缓存 key 与 OCR bridge，而不是只按模块名找文件。
- 动作：PR付款当前主核对能力已接入最新链路，关联单据侧以展示和人工判断为主；后续增强应优先补 PR 特有自动判断规则。

### 2026-04-16 详情页进入不能自动审核

- 现象：点进付款单后面板自动开始审核，违背“用户点击才触发”的预期。
- 原则：进入详情页只做被动缓存回放；缓存未命中也保持待命。
- 动作：`content.js` 的路由进入和初始化默认 `autoRun: false`，只有页面内 `自动审核` 点击事件允许缓存未命中后自动开始。

### 2026-04-16 批量缓存必须能被详情页读回

- 现象：批量审核完成后，进入单个付款单仍读不到缓存并重新审核。
- 原则：写缓存和读缓存的流程号规范必须完全一致，不能一边用 URL id，一边用业务流程号。
- 动作：缓存键统一使用大写 `processCode`，详情页读取时优先结合 URL 和页面快照识别业务流程号。

### 2026-04-16 详情页入口必须有页面内兜底

- 现象：有时单个付款单没有悬浮按钮，用户无法稳定触发审核。
- 原则：入口要由全站常驻脚本挂到 OA 页面结构上，悬浮面板只负责展示。
- 动作：`list_page.js` 在详情页按钮区右侧插入 `自动审核`；找不到按钮区时显示固定兜底入口，并在按钮区出现后迁移。

### 2026-04-15 架构变化要同步文档

- 现象：实现已经从串行变成异步并行，但文档仍按旧模型描述。
- 原则：`requestId` 隔离、受控并发、OCR bridge、缓存失效都属于运行模型，不能只写在代码里。
- 动作：根 README、文档索引和重构计划同步记录当前模型。

### 2026-04-15 签名附件链接不能长期缓存

- 现象：面板里的发票来源链接过一阵打开变成 `Request has expired`。
- 原则：带签名的 COS URL 只能短期使用，UI 里长期保留的是“可刷新来源”，不是旧签名。
- 动作：点击来源时由 background 重新读取详情并刷新对应附件 URL。

### 2026-04-14 OCR 复用要放到宿主页隔离世界

- 现象：批量附件分析中反复初始化 OCR worker，耗时和内存都不稳定。
- 原则：background 负责编排，worker 生命周期放到宿主页 `ISOLATED` world。
- 动作：使用 OCR bridge 复用 worker 池，批量结束和空闲时释放。

## 排查顺序速查

1. 入口没出现：先查是否在 `/workflow/process/detail/<id>`，再查 `list_page.js` 是否注入，最后看按钮区定位和兜底入口是否被清理。
2. 进详情页自动跑：查 route-change、初始化和 hydrate 路径有没有把 `autoRun` 传成 `true`。
3. 批量缓存读不到：查 background 写入键、详情页识别到的 `processCode`、`buildTag`、`cachedDay` 是否一致。
4. 进度乱跳或结果被覆盖：查 `requestId` 是否生成、透传、消费一致，旧回调是否被丢弃。
5. 来源链接打不开：查是否缓存了过期签名 URL，点击时是否重新刷新凭证。
6. OCR 很慢或卡住：查是否重复初始化 worker、是否未释放池、是否对同一附件重复 OCR。
7. 自动化打不开 OA：先查代理绕过和内网白名单，再判断是否为 OA 自身页面错误。
